        Trilhas Linux e Git/GitHub
        
            
        Linux entra porque NOC/SOC/DevOps vivem de terminal, logs e SSH. Git entra porque seu portfolio precisa ser publicado e legivel.
        
          
        
        
        
        
        
          
        
            Linux 1: terminal basico
            `pwd`, `ls`, `cd`, `cat`, `less`, `head`, `tail`, `grep`, `find`, `ip addr`, `ping`, `ss`, `curl`.
            
        Entregavel: README com 12 comandos, o que fazem e um exemplo real.
        
          
        
          
        
            Linux 2: permissoes e processos
            `chmod`, `chown`, usuarios/grupos, `ps`, `top`, `systemctl`, servicos e arquivos em `/var/log`.
            
        Entregavel: mini runbook para diagnosticar servico parado.
        
          
        
          
        
            Linux 3: rede e SSH
            SSH, portas, DNS, firewall local, rotas, `journalctl`, `auth.log` e troubleshooting remoto.
            
        Entregavel: checklist de acesso SSH falhando.
        
          
        
          
        
            Git 1: portfolio minimo
            `git init`, `status`, `add`, `commit`, `remote`, `push`, README e `.gitignore`.
            
        Entregavel: primeiro repo de lab com README publicavel.
        
          
        
          
        
            Git 2: rotina profissional
            Branch, issue, commit pequeno, diff, pull request e historico limpo.
            
        Entregavel: issue descrevendo melhoria de um lab e commit fechando a issue.
        
          
        
          
        
            GitHub Pages
            Publicar HTML estatico, colocar link no README e usar o projeto como evidencia no LinkedIn.
            
        Entregavel: um lab acessivel por URL publica.
